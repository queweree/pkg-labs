# Лабораторная работа №2 — Чтение информации из графических файлов

## Назначение

Веб-приложение вручную читает метаданные растровых изображений без сторонних библиотек метаданных.

Поддерживаются:

- JPG / JPEG
- GIF
- TIFF
- BMP
- PNG
- PCX

## Архитектура для группы 10А

Приложение разделено на три логических слоя.

### 1. Presentation Layer — `index.html` + `styles.css`

Отвечает за интерфейс:

- выбор папки или набора файлов;
- таблицу результатов;
- прогресс обработки;
- счетчики корректных, поврежденных и неподдерживаемых файлов;
- фильтр по результатам.

### 2. Core / Business Logic Layer — `app.js`

Отвечает за:

- получение списка выбранных файлов;
- очередь обработки;
- запуск нескольких Worker;
- распределение файлов между Worker;
- подсчет прогресса;
- обновление таблицы и статистики;
- обработку ошибок Worker;
- локальный fallback для `file://`.

### 3. Data / Parsing Layer — `worker.js`

Отвечает за побайтовый анализ форматов.

Определение формата выполняется по сигнатурам:

- JPEG — `FF D8 FF`
- PNG — `89 50 4E 47 0D 0A 1A 0A`
- GIF — `GIF87a` / `GIF89a`
- BMP — `BM`
- TIFF — `II 2A 00` / `MM 00 2A`
- PCX — `0A`

Сторонние библиотеки для получения метаданных не используются.

## Что читается

### BMP

Вручную читаются `BITMAPFILEHEADER` и `BITMAPINFOHEADER`:

- ширина;
- высота;
- глубина цвета;
- `biCompression`;
- количество цветов палитры;
- `biXPelsPerMeter` / `biYPelsPerMeter`.

Распознаются `BI_RGB`, `BI_RLE8`, `BI_RLE4` и дополнительные коды BMP.

### PNG

Вручную читаются:

- сигнатура;
- `IHDR`;
- ширина и высота;
- bit depth;
- color type;
- compression method;
- filter method;
- `pHYs`, если он присутствует, для получения DPI.

Также проверяется наличие `IEND`.

### JPEG

Вручную ищутся JPEG-маркеры:

- SOF для размеров и precision;
- JFIF для разрешения;
- EOI `FF D9` для проверки целостности.

Весь JPEG не загружается в память целиком.

### GIF

Читается Logical Screen Descriptor:

- ширина;
- высота;
- глубина цвета;
- наличие и размер глобальной палитры.

Проверяется завершающий trailer `3B`.

### PCX

Читается заголовок:

- размеры;
- bits per pixel;
- количество цветовых плоскостей;
- DPI;
- RLE compression.

### TIFF

Вручную разбираются:

- byte order;
- TIFF magic;
- первый IFD;
- записи IFD;
- типы и размеры значений;
- Width (`256`);
- Height (`257`);
- BitsPerSample (`258`);
- Compression (`259`);
- XResolution (`282`);
- YResolution (`283`);
- ResolutionUnit (`296`).

## Производительность

Читаются только необходимые участки файла:

- заголовки;
- нужные чанки;
- нужные TIFF IFD-значения;
- конец файла для JPEG/GIF/PNG-проверок.

Обработка на опубликованной странице выполняется несколькими Worker, поэтому интерфейс не блокируется.

При прямом открытии `index.html` через `file://` браузер может запрещать создание Worker. Для этого режима приложение использует тот же побайтовый парсер асинхронно в основном потоке. Ошибка запуска Worker не считается повреждением файла.

## Поврежденные файлы

Приложение не падает при некорректных данных.

В статус `Файл поврежден` переводятся, например:

- PNG без `IEND`;
- JPEG без `FF D9`;
- BMP с заголовком больше размера файла;
- BMP с некорректным смещением данных;
- TIFF с IFD за пределами файла;
- файл с неверной сигнатурой при заявленном формате определяется по содержимому, а не по расширению.

## Важно

Расширение файла не используется как источник истины: формат определяется по байтовой сигнатуре.
