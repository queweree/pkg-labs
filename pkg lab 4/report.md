# Аналитический отчёт: растровые алгоритмы

## Цель

Реализовать и визуально исследовать алгоритмы растеризации отрезков и кривых: пошаговый алгоритм, ЦДА, Брезенхем для отрезка и окружности, антиалиасинг Ву и целочисленный алгоритм Кастла–Питвея для параболической дуги. Сравнить их производительность на виртуальном растре.

## Архитектура

Приложение разделено на вычислительное ядро и отображение.

- **VirtualGrid** — двумерный числовой массив `Float32Array`. Значение 0 означает незаполненную ячейку, значение в диапазоне (0, 1] — интенсивность пикселя.
- **Raster algorithms** — получают координаты и объект-цель с единственным методом `setPixel(x, y, intensity)`. Алгоритмы не используют Canvas API и не рисуют экранные примитивы.
- **GridPainter / UI** — после вычисления читает готовый массив, рисует увеличенные ячейки, сетку, координатные оси и подписи.
- **Benchmark** — заранее генерирует исходные данные, затем суммирует высокоточные измерения работы алгоритмов на растре 512 × 512. Обновление интерфейса выполняется между пакетами и не входит в суммируемые интервалы.

При отображении целочисленная точка `(x, y)` адресует одну ячейку. В текущей сетке диапазон координат равен `x = −30…30`, `y = −20…20`, а линейный индекс равен `(20 − y) · 61 + (x + 30)`. Ось `y` направлена вверх в математической модели; строка массива для верхней части экрана соответствует большим значениям `y`.

## Реализованные методы

### Пошаговый алгоритм

Ведущая координата перебирается по целым значениям, вторая рассчитывается непосредственно по уравнению прямой. Для крутых линий роли координат меняются местами. На шаге вычисляются выражение с наклоном и округление.

### ЦДА (DDA)

Число шагов определяется как `N = max(|Δx|, |Δy|)`. Приращения составляют `xStep = Δx/N`, `yStep = Δy/N`. После каждого приращения координаты округляются к ближайшей дискретной ячейке. Для отрезка длиной `N` выполняется `N + 1` записей точек.

### Брезенхем для отрезка

Используется обобщённая форма для всех октантов. Она сохраняет знаки смещения, берёт абсолютные приращения и поддерживает целочисленную ошибку:

`dx = |x₁ − x₀|`, `dy = −|y₁ − y₀|`, `err = dx + dy`.

На каждой итерации `e₂ = 2 · err`. Если `e₂ ≥ dy`, обновляется X и ошибка; если `e₂ ≤ dx`, обновляется Y и ошибка. Проверки независимы, поэтому возможен диагональный шаг. На пиксельный шаг не требуется вычисление деления с плавающей точкой.

### Брезенхем для окружности

Строится один октант окружности с начальной ошибкой `d = 3 − 2r`. Каждая найденная точка зеркально переносится в восемь симметричных позиций. Поэтому окружность обходится без вычисления синуса, косинуса или квадратного корня на каждом шаге.

### Ву (сглаживание)

Для линии с дробной координатой `y = floor(y) + f` соседние пиксели получают интенсивности `1 − f` и `f`. При крутом наклоне оси меняются местами. Значения сохраняются в числовом массиве и при выводе становятся прозрачностью пикселей. Это не бинарная имитация сглаживания, а вычисление двух граничных интенсивностей.

### Кастла–Питвея

Параболическая дуга задаётся тремя целочисленными точками — начальной, контрольной и конечной. На их основе рассчитываются коэффициенты неявного конического уравнения второго порядка. Дальше применяется схема конечных разностей: управляющие значения обновляются сложением, а следующий шаг выбирается между квадратным и диагональным. Предельный предохранитель и явная установка концов дуги защищают интерфейс от зацикливания на вырожденных входных данных.

## Расчётный пример: отрезок A(2, 1) → B(9, 5)

`Δx = 9 − 2 = 7`, `Δy = 5 − 1 = 4`.

### ЦДА

`N = max(7, 4) = 7`; `xStep = 7/7 = 1`; `yStep = 4/7 ≈ 0,5714`.

После каждого шага координаты округляются. Последовательность растровых точек:

`(2,1), (3,2), (4,2), (5,3), (6,3), (7,4), (8,4), (9,5)`.

### Брезенхем

В используемой общей форме `dx = 7`, `dy = −4`, `err₀ = dx − |Δy| = 3`. Для каждой текущей точки считается `e₂ = 2 · err`. Если `e₂ ≥ −4`, выполняется шаг по X; если `e₂ ≤ 7`, шаг по Y. Для точек примера:

| Точка | `err` до шага | `e₂` | Решение |
|---|---:|---:|---|
| (2, 1) | 3 | 6 | X и Y |
| (3, 2) | 6 | 12 | X |
| (4, 2) | 2 | 4 | X и Y |
| (5, 3) | 5 | 10 | X |
| (6, 3) | 1 | 2 | X и Y |
| (7, 4) | 4 | 8 | X |
| (8, 4) | 0 | 0 | X и Y |
| (9, 5) | — | — | Конечная точка |

Полученная последовательность совпадает с приведённой для ЦДА, но решение Брезенхема строится на целочисленной ошибке.

### Пошаговый метод

Для данного отрезка наклон `m = Δy/Δx = 4/7 ≈ 0,5714`. Для целых `x = 2…9` рассчитывается `y = round(1 + m(x − 2))`; получаются те же восемь пикселей. В отличие от ЦДА, здесь координата напрямую вычисляется из уравнения, а не повторным прибавлением приращения.

### Один пиксель при сглаживании Ву

Для вертикальной полосы `x = 3` идеальная координата равна `y = 1 + 4/7 ≈ 1,5714`. Доля `f ≈ 0,5714`, поэтому пиксели `(3,1)` и `(3,2)` получают интенсивности примерно `0,4286` и `0,5714` соответственно (без учёта граничной поправки на концах линии). Сумма долей равна единице.

## Анализ сложности и производительности

Для отрезка длины `N = max(|Δx|, |Δy|)` все три базовых алгоритма выполняют `O(N)` шагов, но число и тип операций различаются.

- Пошаговый метод рассчитывает уравнение прямой заново на каждом шаге; в теле цикла присутствуют умножение/деление и округление.
- ЦДА использует постоянные дробные приращения и округляет координаты на каждом шаге.
- Брезенхем использует целочисленные сравнения и сложение/вычитание для обновления ошибки. Поэтому у него часто ниже постоянная стоимость итерации и отсутствует накопление погрешности дробного шага.
- Для окружности алгоритм Брезенхема работает примерно за `O(r)` шагов, записывая симметричные точки; каждый шаг порождает до восьми записей.
- Сглаживание Ву имеет линейное число шагов, но обычно записывает две точки на колонку/строку вместо одной.

Одинаковая асимптотика не означает равную длительность. На результат влияют длина линии, ветвления, количество записей в память, движок JavaScript и устройство. Поэтому вывод о том, что ЦДА медленнее Брезенхема в данной реализации, делается по фактическим графикам, а не по теоретической сложности одной лишь операции.

## Экспериментальная методика

Стресс-тест генерирует 100 000 отрезков с направлением во всех восьми октантах и 50 000 окружностей с разным радиусом. Тестовые координаты заранее подготавливаются фиксированным генератором псевдослучайных чисел. Отрезки и окружности растеризуются в отдельный `Uint8Array` размером 512 × 512. Временные измерения суммируются по пакетам алгоритмической работы с помощью `performance.now()`; ожидание между пакетами и построение графиков не включаются.

Первый график показывает накопленное время для разного количества обработанных отрезков и окружностей. Второй график показывает время обработки 1 000 линий для длин 16, 32, 64, 128, 192 и 256 пикселей. Чтобы сравнить методы на одном устройстве, следует запускать тест с каждым алгоритмом отрезка, не меняя окружность или параметры браузера.

**Важно:** точные миллисекунды зависят от устройства, браузера и нагрузки. Они измеряются непосредственно приложением. В скачиваемой версии отчёта после каждого завершённого теста автоматически добавляются фактические значения, а не заранее вписанные демонстрационные цифры.
